## 测试问题排查

### 🔍 问题：unified 命令未识别

#### 问题现象

运行 `opencode unified` 时，显示帮助信息而不是执行命令，说明命令未被识别。

#### 原因分析

1. **使用已安装的二进制文件**: `opencode` 命令指向全局安装的版本，不包含新添加的 `unified` 命令
2. **代码未重新构建**: 即使代码已修改，如果没有重新构建，新命令不会生效
3. **开发模式未启用**: 需要使用开发模式运行才能使用最新代码

#### ✅ 解决方案

**方案 1: 使用开发模式运行（推荐）**

```bash
# 进入 OpenCode 目录
cd /media/hzm/data_disk/opencode/packages/opencode

# 使用开发模式运行
bun run --conditions=browser ./src/index.ts unified \
  --dir /tmp/test-project \
  --requirement "测试需求"
```

**方案 2: 重新构建项目**

```bash
# 进入 OpenCode 目录
cd /media/hzm/data_disk/opencode/packages/opencode

# 构建项目
bun run build
```

**方案 3: 创建开发环境别名**

在 `~/.bashrc` 或 `~/.zshrc` 中添加：

```bash
# OpenCode 开发模式别名
alias opencode-dev='cd /media/hzm/data_disk/opencode/packages/opencode && bun run --conditions=browser ./src/index.ts'
```

## 使用方式

### CLI 使用

```bash
# 简单需求
opencode unified --dir /path/to/project --requirement "帮我运行这个项目"

# 复杂需求（自动创建规划文件）
opencode unified --dir /path/to/project --requirement "实现用户登录功能"

# 强制使用 Manus 模式
opencode unified --dir /path/to/project --requirement "实现功能" --useManus

# 指定模型和 Agent
opencode unified --dir /path/to/project --requirement "实现功能" --model "anthropic/claude-3.5-sonnet" --agent "frontend"
```

### 代码使用

```typescript
import { unifiedEntry } from '@opencode-ai/opencode/unified'

const result = await unifiedEntry({
  directory: '/path/to/project',
  requirement: '实现用户登录功能',
  sessionID: 'session-id',
  useManus: true,
})

if (result.success) {
  console.log('Session ID:', result.sessionID)
  console.log('Planning files created:', result.planningFilesCreated)
}
```

## 技术实现亮点

1. **模块化设计**: 每个功能独立模块，易于测试和维护
2. **降级方案**: 需求解析支持 LLM 失败时的规则匹配降级
3. **文件锁机制**: 使用 proper-lockfile 确保规划文件更新的原子性
4. **缓存优化**: Hooks 适配器使用 500ms TTL 缓存，减少文件读取
5. **事件式 Hooks**: 将命令式 Hooks 转换为 OpenCode 事件式 Hooks
6. **智能调度**: Agent 能力矩阵 + 任务匹配 + 执行计划生成
