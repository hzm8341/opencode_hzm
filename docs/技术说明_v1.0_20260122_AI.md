# OpenCode 项目技术说明

> 版本: v1.0
> 日期: 20260122
> 文档类型: 技术架构说明

## 1. 项目概述

OpenCode 是一个开源的 AI 编码助手项目，提供终端用户界面(TUI)、Web界面和桌面应用，支持多模型、多Agent系统和插件化架构。

### 1.1 核心特性

- **多模型支持**: 支持 Claude、OpenAI、Google 或本地模型
- **终端界面**: 为终端用户构建的强大 TUI
- **Web界面**: 通过浏览器或桌面应用访问
- **插件系统**: 可扩展的插件架构（如 Oh My OpenCode）
- **LSP 支持**: 开箱即用的语言服务器协议支持
- **多Agent系统**: 针对不同任务的专业化 Agent

## 3. 项目架构

### 3.1 Monorepo 结构

项目采用 Turborepo 管理，包含以下主要包：

```
packages/
├── opencode/              # 核心包（CLI 和服务器）
├── sdk/js/               # JavaScript/TypeScript SDK
├── plugin/               # 插件系统核心
├── plugin-oh-my-opencode/# Oh My OpenCode 插件
├── console/              # 控制台应用
├── web/                 # Web 文档站点
├── desktop/             # 桌面应用
├── openwork-desktop/    # OpenWork 桌面应用
├── app/                # Web 应用
├── ui/                 # UI 组件库
├── util/               # 工具函数库
├── script/            # 脚本工具
├── identity/          # 身份认证
├── function/          # 云函数
├── extensions/        # 扩展
└── slack/            # Slack 集成
```

### 4.4 统一 Agent 执行流程

#### 6步流程

1. **阶段1: 任务解析** - 理解核心需求，澄清成功标准
2. **阶段2: 智能分解** - 分解为可执行步骤，确定资源需求
3. **阶段3: 并行执行** - 多线程收集/处理，实时进度跟踪
4. **阶段4: 综合构建** - 信息融合和逻辑构建
5. **阶段5: 质量保证** - 自检和端到端验证
6. **阶段6: 结果交付** - 按需格式化并提供执行摘要

## 5. 开发工作流

### 5.1 规划优先原则 (Planning First Principle)

**强制要求**: 开始任何新任务之前，必须使用 `plan` agent 创建详细计划并保存为文档，然后使用 `build` agent 逐步实现。

```bash
# 步骤 1: 创建计划
bun dev run --agent plan --model opencode/gpt-5-nano \
  "Create a detailed plan: [your task]. Save to docs/task_plan_v1.0_$(date +%Y%m%d)_AI.md"

# 步骤 2: 基于计划实现
bun dev run --agent build --model opencode/grok-code \
  "Implement according to docs/task_plan_v1.0_date_AI.md"
```

### 5.2 开发命令

#### 核心命令

```bash

# 开发模式（运行 TUI）
```

### 5.3 代码风格

#### 命名规范

- **变量/函数**: camelCase
- **类/命名空间**: PascalCase
- **常量**: UPPER_SNAKE_CASE

#### 代码组织

- **命名空间模式**: `Tool.define()`, `Session.create()`
- **相对导入**: 本地模块使用相对导入
- **命名导入**: 优先使用命名导入

#### 类型安全

- **Zod schemas**: 所有输入验证使用 Zod
- **TypeScript interfaces**: 结构定义使用 TS 接口
- **Result patterns**: 错误处理使用 Result 模式

#### 文件结构

- 命名空间组织
- 单一职责原则
- 避免不必要的解构
- 避免不必要的 `try`/`catch`
- 避免使用 `any` 类型

### 5.4 日志和错误处理

#### 日志

```typescript
import { Log } from "./util/log"

// 创建日志实例
const log = Log.create({ service: "name" })

// 记录日志
log.info("action", { data })
log.error("error", { error })
```

#### 错误处理

- 使用 Result 模式
- 避免在工具中抛出异常
- 使用 NamedError 结构化错误

## 总结

OpenCode 是一个功能强大、架构优雅的 AI 编码助手项目。通过模块化的 Monorepo 结构、插件化架构和多 Agent 系统，提供了灵活且强大的开发辅助能力。

**核心优势**:

- 100% 开源
- 提供商无关（支持多种 AI 模型）
- 开箱即用的 LSP 支持
- 专注于 TUI 体验
- 客户端-服务器架构
- 丰富的插件和技能生态系统

**技术亮点**:

- Bun + TypeScript 现代化技术栈
- SolidJS 响应式 UI
- Zod 类型安全
- MCP 协议支持
- 统一的 Agent 执行流程
- 规则注入系统

项目非常适合希望在终端环境中获得强大 AI 编码辅助的开发者，同时也支持 Web 和桌面应用，满足不同用户的需求。
