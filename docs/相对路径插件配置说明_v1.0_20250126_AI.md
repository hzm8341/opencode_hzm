**版本**: v1.0  
**日期**: 2025-01-26  
**AI模型**: Claude-4

---

## 概述

本文档说明如何配置 OpenCode 使用相对路径加载本地插件，确保在不同电脑和文件夹下都能正常工作。

## 问题

使用绝对路径（如 `file:///Users/minghu/Downloads/opencode_hzm/...`）会导致：
- 换电脑后路径失效
- 移动项目文件夹后路径失效
- 不同用户无法使用

## 解决方案

使用 OpenCode 的自动插件发现机制，通过 `.opencode/plugin/` 目录加载插件。

### 方法：使用符号链接

在 `.opencode/plugin/` 目录创建符号链接指向插件文件：

```bash
mkdir -p .opencode/plugin
ln -sf ../../packages/plugin-oh-my-opencode/src/index.ts .opencode/plugin/oh-my-opencode.ts
```

### 工作原理

OpenCode 会自动扫描 `.opencode/plugin/` 和 `.opencode/plugins/` 目录下的 `.ts` 和 `.js` 文件，并自动加载它们。符号链接会被自动解析，所以可以使用相对路径。

## 当前配置

### 项目配置

**文件**: `.opencode/opencode.jsonc`

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  // 插件通过 .opencode/plugin/ 目录自动加载，无需在配置中指定
  "instructions": ["STYLE_GUIDE.md"],
  "provider": {
    "opencode": {
      "options": {}
    }
  },
  // ... 其他配置
}
```

**符号链接**: `.opencode/plugin/oh-my-opencode.ts`
- 指向: `../../packages/plugin-oh-my-opencode/src/index.ts`
- 使用相对路径，可移植性强

### 全局配置

**文件**: `~/.config/opencode/opencode.jsonc`

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["oh-my-opencode"],
  "provider": {
    "opencode": {
      "options": {}
    }
  }
}
```

**说明**: 全局配置使用 npm 包名，因为全局配置在不同项目间共享，无法使用项目相对路径。

## 目录结构

```
opencode_hzm/
├── .opencode/
│   ├── plugin/
│   │   └── oh-my-opencode.ts -> ../../packages/plugin-oh-my-opencode/src/index.ts
│   └── opencode.jsonc
└── packages/
    └── plugin-oh-my-opencode/
        └── src/
            └── index.ts
```

## 优势

1. **可移植性**: 使用相对路径，可以在任何位置使用
2. **版本控制**: 符号链接可以提交到 Git（如果使用相对路径）
3. **自动发现**: OpenCode 自动扫描并加载插件
4. **无需配置**: 不需要在 `opencode.jsonc` 中指定插件路径

## 验证配置

运行以下命令验证插件是否正确加载：

```bash
cd /path/to/project
bun dev run --print-logs "测试" 2>&1 | grep "loading plugin"
```

如果看到类似输出，说明插件已成功加载：
```
INFO service=plugin path=file:///path/to/.opencode/plugin/oh-my-opencode.ts loading plugin
```

## 其他项目使用

如果要在其他项目中使用相同的配置：

1. **克隆项目**后，符号链接会自动指向正确的相对路径
2. **确保目录结构一致**：插件文件相对于 `.opencode/plugin/` 的路径保持不变

## 故障排查

### 问题1: 符号链接失效

**症状**: 插件未加载

**解决方案**:
```bash
# 检查符号链接
ls -la .opencode/plugin/
readlink .opencode/plugin/oh-my-opencode.ts

# 重新创建符号链接
rm .opencode/plugin/oh-my-opencode.ts
ln -sf ../../packages/plugin-oh-my-opencode/src/index.ts .opencode/plugin/oh-my-opencode.ts
```

### 问题2: 路径不正确

**症状**: 找不到插件文件

**解决方案**:
1. 确认插件文件存在：`ls -la packages/plugin-oh-my-opencode/src/index.ts`
2. 检查相对路径是否正确：从 `.opencode/plugin/` 到插件文件的相对路径
3. 使用绝对路径测试：`readlink -f .opencode/plugin/oh-my-opencode.ts`

### 问题3: 权限问题

**症状**: 无法读取插件文件

**解决方案**:
```bash
# 检查文件权限
ls -la packages/plugin-oh-my-opencode/src/index.ts

# 确保文件可读
chmod +r packages/plugin-oh-my-opencode/src/index.ts
```

## Git 配置

如果要将符号链接提交到 Git：

```bash
# 检查 Git 是否跟踪符号链接
git ls-files .opencode/plugin/

# 如果 Git 不支持符号链接，可以：
# 1. 使用 Git 的符号链接支持（需要配置）
# 2. 或者使用脚本在克隆后自动创建符号链接
```

创建 `scripts/setup-plugin-link.sh`:

```bash
#!/bin/bash
mkdir -p .opencode/plugin
ln -sf ../../packages/plugin-oh-my-opencode/src/index.ts .opencode/plugin/oh-my-opencode.ts
echo "Plugin link created"
```
