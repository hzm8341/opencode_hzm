#### 步骤 3: 传输到远程系统

```bash
# 创建远程目录
ssh hzm@10.200.1.59 "mkdir -p /tmp/opencode_test"

# 传输文件
scp packages/opencode/dist/opencode-linux-x64/bin/opencode \
    hzm@10.200.1.59:/tmp/opencode_test/opencode

# 设置执行权限
ssh hzm@10.200.1.59 "chmod +x /tmp/opencode_test/opencode"
```

#### 步骤 4: 远程系统测试

```bash
# 检查远程系统环境
ssh hzm@10.200.1.59 << 'EOF'
echo "=== 系统信息 ==="
uname -a
cat /etc/os-release | head -5
echo ""
echo "=== 运行时检查 ==="

which node || echo "Node.js: 未安装 (预期)"

echo "=== 可执行文件信息 ==="

ls -lh opencode
file opencode
echo ""
echo "=== 依赖检查 ==="
ldd opencode 2>&1 || echo "无法检查依赖"
EOF

# 测试基本功能
echo "=== 测试 --version ==="
ssh hzm@10.200.1.59 "/tmp/opencode_test/opencode --version"

echo ""
echo "=== 测试 --help ==="
ssh hzm@10.200.1.59 "/tmp/opencode_test/opencode --help" | head -20
```

## 预期结果

### 成功标准

1. **可执行文件可以独立运行**
   - 不依赖系统安装的 Bun
   - 不依赖系统安装的 Node.js

2. **基本命令正常工作**
   - `--version` 输出版本号
   - `--help` 显示帮助信息

3. **依赖关系清晰**
   - 只依赖系统库（glibc 等）
   - 不依赖外部运行时

### 可能的问题

#### 问题 1: 找不到动态库

**症状**:
```
./opencode: error while loading shared libraries: libxxx.so.x: cannot open shared object file
```

**原因**: 缺少系统库依赖

**解决方案**:
- 记录缺失的库
- 在构建时链接静态库，或
- 在文档中说明系统要求

#### 问题 2: 运行时错误

**症状**:
```
Error: Cannot find module 'xxx'
```

**原因**: 某些模块未正确打包

**解决方案**:
- 检查构建脚本
- 确保所有依赖都被包含
- 可能需要修改构建配置

#### 问题 3: Worker 文件路径错误

**症状**:
```
Error: Cannot find worker file at /$bunfs/root/...
```

**原因**: Worker 文件路径在独立可执行文件中无效

**解决方案**:
- 修改代码使用相对路径
- 在构建时复制 worker 文件
- 使用环境变量或可执行文件位置
