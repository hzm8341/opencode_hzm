## 概述

本文档说明如何配置 OpenCode 使用本地的 `oh-my-opencode` 插件，而不是从 npm 安装。

## 配置方式

OpenCode 支持两种方式加载插件：

1. **npm 包名**（如 `"oh-my-opencode"`）- 自动从 npm 安装
2. **file:// 协议路径**（如 `"file:///path/to/plugin.ts"`）- 直接加载本地文件

## 当前配置

### 全局配置

**文件**: `~/.config/opencode/opencode.jsonc`

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["file:///Users/minghu/Downloads/opencode_hzm/packages/plugin-oh-my-opencode/src/index.ts"],
  "provider": {
    "opencode": {
      "options": {}
    }
  }
}
```

**注意**: 全局配置使用绝对路径，适用于固定位置的插件。

### 项目配置

**文件**: `.opencode/opencode.jsonc`

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["file:///Users/minghu/Downloads/opencode_hzm/packages/plugin-oh-my-opencode/src/index.ts"],
  // ... 其他配置
}
```

## 优势

使用本地插件的优势：

1. **无需网络**: 不需要从 npm 下载插件
2. **快速加载**: 直接加载本地文件，速度更快
3. **开发调试**: 可以修改插件代码并立即生效
4. **版本控制**: 插件代码在项目中，便于版本管理

## 路径说明

### 绝对路径格式

```
file:///绝对路径/到/插件文件
```

示例：
```
file:///Users/minghu/Downloads/opencode_hzm/packages/plugin-oh-my-opencode/src/index.ts
```

### 注意事项

1. **路径格式**: 必须使用 `file://` 协议，路径必须是绝对路径
2. **文件存在**: 确保插件文件路径正确且文件存在
3. **权限**: 确保 OpenCode 有权限读取插件文件

## 验证配置

运行以下命令验证插件是否正确加载：

```bash
cd /Users/minghu/Downloads/opencode_hzm
bun dev run --print-logs "测试" 2>&1 | grep -E "(plugin|oh-my-opencode|loading)"
```

如果看到类似输出，说明插件已成功加载：
```
INFO service=plugin path=file:///Users/minghu/Downloads/opencode_hzm/packages/plugin-oh-my-opencode/src/index.ts loading plugin
```

## 切换回 npm 包

如果需要切换回使用 npm 包，只需将配置改为：

```jsonc
{
  "plugin": ["oh-my-opencode"]
}
```

## 故障排查

### 问题1: 插件未加载

**症状**: 日志中没有插件加载信息

**解决方案**:
1. 检查文件路径是否正确
2. 确认文件是否存在：`ls -la /path/to/plugin/index.ts`
3. 检查文件权限：确保可读

### 问题2: 路径错误

**症状**: 错误信息显示找不到文件

**解决方案**:
1. 使用绝对路径
2. 确保路径中包含 `file://` 协议
3. 检查路径中的特殊字符是否正确转义

### 问题3: 插件加载失败

**症状**: 插件文件存在但加载失败

**解决方案**:
1. 检查插件文件语法是否正确
2. 确认插件导出了正确的格式
3. 查看详细错误日志：`bun dev run --print-logs "测试"`
